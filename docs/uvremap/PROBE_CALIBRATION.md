# プローブ検証の校正記録(契約 §3.1)

`uvremap_core.probe_verify` の仕様と、しきい値の根拠となる測定。数値はすべて
`python sp_maya_livesync/tests/test_uvremap_core.py --calibrate` の出力(実行コマンド・日時は末尾)で、
同じコマンドで再現できる。契約の文言と異なる点は [`QUESTIONS.md`](QUESTIONS.md) の Q1(窓の方式)、Q2(線形光)、
Q3(tau)、Q8(平滑なテクスチャの 2% ずれ)に理由と判断依頼を書いた。

## (a) 採用したプローブの仕様

| 項目 | 内容 | 契約からの差 |
|---|---|---|
| 点の選び方 | TS の三角形から 3D 面積比例で `n=512` 点(固定シード 0)、三角形内は一様な重心座標。3D 面積 0・旧/新UV面積 0 の三角形は候補から外す | なし |
| 旧/新の位置 | 同じ三角形・同じ重心座標から旧UV位置と新UV位置を求め、旧テクスチャは旧UVで、新テクスチャは新UVで読む | なし |
| 窓の方式 | `footprint="centered"`(既定): **プローブ点を中心とする箱型平均**。縁のテクセルは重なり面積で重み付けし、画像の外は端の値で延長する | **Q1**: 契約の読み方「画像の格子に固定した箱型縮小」(`footprint="lattice"`)は残してあるが既定にしていない |
| 窓の大きさ(新側) | `s = max(1, min(W,H)//256)` テクセル四方(タイルの解像度ごと) | なし(契約の `s` と同じ) |
| 新旧のテクセル密度の換算 | `match_density=True`(既定): 三角形ごとに `rho = sqrt(新UV面積×Wn×Hn / (旧UV面積×Wo×Ho))`(新テクセルが旧テクセル1個に対して線方向に何個か)を求め、旧側の窓を `clip(s / rho, 1, 4s)` テクセル四方にする。新旧の窓が同じ表面の長さを覆う | **Q1**(契約に記述なし) |
| 平均の空間 | `colorspace="srgb"` かつ `kind != "normal"` のとき、色チャンネルを線形化して平均し、sRGB に再符号化した値で比較する(アルファは生値)。scalar・raw・法線は生値のまま平均 | **Q2**(契約に記述なし) |
| 誤差 | color/scalar: チャンネル最大の絶対差。normal: 旧法線を UV ヤコビアンで補正(`normal_mode="uv"`)したものと新法線の角度[deg](ゼロベクトルは 180°) | なし |
| tau | **0.10**(color/scalar)。法線は 8°。`max_bad_fraction = 0.02` | **Q3**: 契約は 0.08。法線 8° と 0.02 は契約のまま |
| 判定 | `n_bad / n_valid > 0.02` → `fail`。そうでなく `n_valid < 64` → `inconclusive`(`notes` に `n_valid N < 64`)。`n_valid == 0` → `inconclusive`。両条件が同時なら `fail` を優先 | **Q5**(契約に優先順位なし) |
| 除外 | `island_border`: 島の境界から 2 テクセル(縮小格子 `W//s × H//s` 上の 2 セル = 元画像で約 `2s` テクセル)以内、旧・新の両レイアウトで判定。`uv_overlap`: 新UVの重なりとその 1 セル近傍。`tile_straddle`: UDIM 境界をまたぐ三角形(旧・新)。`udim_out_of_range`: UDIM の範囲外(u 0〜9、v 0〜99 の外)。`old_tile_missing`: 旧タイルが無い点。変換から除外された面(非多様体・UVなし)は候補にならない | 契約の列挙に `udim_out_of_range`・`old_tile_missing` を追加 |
| 不合格として数える点 | 新UVが指すタイルが `new_tiles` に無い点(タイル番号の取り違え・欠落)は誤差 1.0(法線は 180°)の不合格 | 契約に記述なし |
| 注記 | 縮小係数 `s` の最小が 4 未満で不合格点が 1 つでもあれば `notes` に `low_resolution_probe` | 契約に記述なし |

しきい値は定数 `PROBE_TAU`、`PROBE_NORMAL_DEG`、`PROBE_MAX_BAD_FRACTION`、`PROBE_MIN_VALID`、`PROBE_BORDER_TEXELS`、
`PROBE_FOOTPRINT` と、`probe_verify` のキーワード引数で上書きできる(`ProbeReport.params` に判定に使った値を記録)。

### しきい値の選定(tau)

正例は下の (b) の全シナリオ、負例は (c) の「必須」の不具合(1% のずらしと、平滑なテクスチャの 2% のずらしを除く)。

- 色は `tau=0.08` でも `n=2000` では 0.75% で余裕 2.7 倍だが、既定の `n=512` では 40 シード中 2 回 fail した
  (下の「既定 n=512 の偽陽性」)。`tau=0.10` で 0 回になる。
- `tau=0.12` 以上は、平滑なテクスチャの 3% のずらし(検出の下限、Q8)を 0.9% 以下でしか検出できず、必須の負例を落とす。
  したがって、測定した刻み(0.04〜0.16)の中では `tau=0.10` だけが、正例の余裕と負例の検出を両立する(`0.08` は `n=512` の偽陽性、`0.12` は検出落ち)。
- 法線は 2°〜12° のどれでも正例の不合格点が 0%、負例の最弱が 7.9〜9.4%。契約の 8° をそのまま使う。

## (b) 偽陽性の測定(正しい変換は pass しなければならない)

### 条件

- 合成メッシュ(立方体を球に射影、6シェル)に解析的な信号を焼いた地上真値。レイアウト A(全シェルが 1001)から
  B(移動・回転・拡大・反転で 1001/1002 に分かれる)など 6 通り。
  色は 1024²、法線は 512²。`n=2000` 点・シード 0。
- 信号: smooth(平滑)、detail(文字様の細部)、noise(3D空間の白色ノイズ。セル幅は 1024² で約 2 テクセル)。
  raw と sRGB。
- 区分: 「細部ノイズ」= detail/noise、「シーム周辺」= 元テクスチャにパディングが無くシームが荒れる条件
  (`unpadded source`)と、すべてのシナリオの島境界の除外、「UDIM移動」= シェルが 1001 から 1002 へ移る A→B、B→A、B→rot270_mirror。
- 「最大誤差」は 1 点の最大値であり、判定の量ではない(判定は不合格点の割合)。最大誤差が `tau` を超えても、
  不合格点が 2% 以下なら pass する。「2%までの余裕」は 2% を不合格点割合で割った倍率。

### 既定 n=512 の偽陽性(40 シード)

点数が既定の 512 だと割合の揺れが大きく、`n=2000` の表より余裕が小さい。

| scenario | fail@tau=0.08 | worst bad% | mean bad% | fail@tau=0.10 | worst bad% | mean bad% |
|---|---|---|---|---|---|---|
| noise/srgb A->B | 2 / 40 | 2.09% | 1.23% | 0 / 40 | 1.27% | 0.59% |
| noise/srgb A->scaled | 0 / 40 | 0.86% | 0.26% | 0 / 40 | 0.62% | 0.09% |
| noise/srgb B->rot270_mirror | 0 / 40 | 0.63% | 0.16% | 0 / 40 | 0.41% | 0.05% |
| noise/raw B->rot270_mirror | 0 / 40 | 0.21% | 0.01% | 0 / 40 | 0.00% | 0.00% |
| detail/srgb A->B | 0 / 40 | 0.63% | 0.09% | 0 / 40 | 0.21% | 0.03% |

`tau=0.10` の最悪は `noise/srgb A->B` の **1.27%**(2% まで **1.6 倍**)。`n=2000` の 5.4 倍より小さいので、
既定の `n=512` での実際の余裕はこの 1.6 倍と見るべきである。ノイズの粒度がさらに細かい、または sRGB のコントラストが
さらに高いテクスチャでは、1024² でも fail し得る(未測定)。

## (c) 故意の不具合の検出

### 条件

出力(正しい変換の結果)に次を加えて `probe_verify` に渡す。`inject_*` はテストファイル内の関数。

| 不具合 | 注入方法 |
|---|---|
| U方向のずれ | 全タイルを U 方向にタイル幅の 1%・2%・3%・5% だけ環状にずらす |
| 1シェルのみ反転 | 6 つのシェルそれぞれについて、その外接矩形内だけを左右反転 |
| タイル番号の取り違え | 1001 と 1002 の中身を入れ替え / 1002 を 1003 と取り違え / 1002 を欠落 |
| 領域の欠落 | 被覆テクセルの 2%・3%・5%・10% を縦帯状に黒く欠落 |

- 契約が求める不具合(U方向 2% 以上のずれ、1シェル反転、タイル取り違え、欠落)は、**平滑なテクスチャの 2% のずれを除いてすべて検出**した。

  1% のずれは要求外(平滑では検出できず、細部とノイズでは検出する)。

## (d) 低解像度での限界と推奨運用

### 限界(測定と実装から)

1. **縮小係数 `s` が 4 未満(1024² 未満)では、テクセル単位の細部ノイズで偽陽性が出る**(上の解像度表)。
   512² で k=1, 2 が fail(3.3% / 2.2%)、256² は k=4 でも fail(3.8%)。実際の写真的・手描きのテクスチャが
   これほど高周波かは別の問題だが、合成データでは再現している。`s<4` で不合格点があると `notes` に `low_resolution_probe` が付く。
2. 512² で k=4 以上の滑らかさなら pass する(0.6%)。ただし既定の `n=512` では一時測定で 1.7%(補足: 校正スクリプト外の測定、
   同じ `Case` で `n=512`・シード 0)と 2% に近く、余裕が小さい。
3. **`inconclusive` になる条件**: (i) 有効点 `n_valid < 64` で不合格が 2% 以下、(ii) `n_valid == 0`(`no_convertible_faces`、
   `no_candidate_triangles` の注記付きを含む)。校正のシナリオでは `n_valid` は点数のおよそ 94%(1024²・`n=2000` で 1873〜1883)で、
   既定の `n=512` なら約 465〜480 点になり(2048²・4タイルの `probe_verify` で 465)、解像度そのものでは `inconclusive` にならない。
   縮小格子の幅 `W//s` は、解像度が 256 以上なら 256〜511 セルに収まるので、島境界の除外の割合は解像度によらずほぼ一定である(実装から。測定はしていない)。
   `inconclusive` になるのは、既定の `n=512` では点の 87.5% 以上が除外される場合(TS が極端に小さい、ほぼ全面が重なり・UDIM 境界またぎ・範囲外など)や、
   `n` を小さくした場合(テスト `test_few_valid_points_is_inconclusive` は `n=40`)。
4. `inconclusive` のときも、不具合があれば `fail` を優先して返す(Q5)。
5. 平滑なテクスチャでは U方向 2% のずれを検出できない(Q8)。解像度と無関係の信号側の限界。
6. 窓は正方形なので、縦横で異なるスケール(非一様)がある変換では窓の覆う領域がずれる。この校正では測っていない(LAYOUT_B は各シェルが一様な 1.0〜1.5 倍で、その範囲では問題なし)。

### 推奨運用

- **1024² 以上(`s>=4`)**: `fail` を公開停止の根拠にしてよい。`inconclusive` は契約どおり「採用して警告」。
  `n` は既定の 512 で足りるが、判定が境界に近い場合(不合格点が 1〜2%)は `n=2000` で再測定すると余裕が見える。
- **512²〜1023²(`s=2〜3`)**: テクセル単位の細部があると偽陽性があり得る。`fail` のとき `low_resolution_probe` 注記が付いたら、
  不合格点の割合を利用者に示し、自動停止でなく警告として扱うか確認を求めるのが安全。1024² での測定では、1 シェル反転の不合格点は 9.3% 以上、
  10% の欠落は 14.1%(512² では測っていないので目安)。
- **512² 未満(`s=1`)**: プローブは平均化せず、偽陽性と本物の不具合を分けられない(256² の k=1 で偽陽性 16.9%)。
  参考表示にとどめ、公開の可否には使わないことを推奨する。
- 色の不合格点は 1.27%(最悪、`n=512`)まで正例で出る。`max_bad_fraction=0.02` を下げない。
- 変換を `normal_mode="off"` で行ったら、`probe_verify` にも `normal_mode="off"` を渡す(Q4)。渡さないと正しい変換が fail になる。
