# 指揮役への質問(プラグイン 1.3.0 / ORDER_SP130)

実装は指示書に合わせてある。決まっていないところは、下の仮の振る舞いを入れてある。変えるときはこの番号で指示してほしい。

## Q1. メッシュ記録の待ち時間

記録は `ProjectEditionEntered` のあと、名前付きの単発タイマーで遅延する。待ち時間の指定が無かったので `_MESH_RECORD_DELAY_MS = 0`(イベントループの次の回)にした。

要実機確認: この時点で `project.last_imported_mesh_path()` が空でないか。空なら、既存の記録は残したまま何も書かない。待ちを伸ばすならミリ秒の指示がほしい。

決定: 初回の待ちは 0ms のまま。

## Q2. 未保存のまま開いて、その後に名前を付けて保存したとき

記録の機会は `ProjectEditionEntered` だけにした。未保存キーでは記録しない。名前を付けて保存したときは、メッシュ記録を新キーへ移すだけで、パスの取り直しはしない。未保存中に一度も記録していなければ、プロジェクトを開き直すまで記録が無い。

保存のタイミングでも記録するなら指示がほしい。

決定: 名前を付けて保存したあと、キー移行の次にメッシュを記録する。

## Q3. メッシュファイルが無い・読めないとき

パスが空でないのに `stat` できない、または sha1 の読み込みに失敗したときは `None` を返し、記録しない。既存の値は消さない。

決定: ファイルが無い・読めないときは記録しない。既存の値は残す。

## Q4. sha1 の再利用は size と mtime_ns だけ

指示どおり、前回の `size` と `mtime_ns` が同じならパスが違っていても前回の sha1 を使う。パスも一致しているときだけ再利用する方がよければ指示がほしい。

決定: path・size・mtime_ns がすべて同じときだけ sha1 を使い回す。

## Q5. 同期回数と R2-09 の修正案

指示書に合わせ、成功でなくても 1 件以上置き換えた書き出しが終わったときに `sync_count` を増やす。レビュー R2-09 の修正案(非成功とキャンセルでは増やさない)とは違う。指示書を優先した。

決定: 1 件以上置き換えたら、成功でなくても `sync_count` を増やす。

## Q6. 非成功の Final と「同期待ち」表示

`final_pending` を下ろすのは、ok の Final と、変更が無くてスキップした Final だけ。Warning / Error / キャンセル / 例外では下ろさない。以前の Warning / Error は成功扱いで下ろしていた。

決定: 非成功の Final では `final_pending` を下ろさない。

## Q7. プレビューの失敗文

Final は非成功のとき「最終書き出しは完了しませんでした(状態: …)」。プレビューも同じ調子で「プレビュー同期は完了しませんでした(状態: …)」を出す。指示が明記している失敗文は Final だけなので、プレビューに失敗文が不要なら外す。

状態の文言は「成功 / 警告 / エラー / キャンセル / 例外」。結果ファイルの `status` は英語のまま(`success` など)。

決定: プレビューにも失敗文を出す。キャンセルと例外は既存の文だけにする。

## Q8. サブフォルダ名の保存が失敗したとき

`dest_root` を決めた直後の `save_config`(サブフォルダ名)が例外になると、結果ファイルは書かない。書き出し本体(`export_project_textures` 以降と、その前のフォルダ作成)の例外では書く。この境目でよいか。

決定: サブフォルダ名の `save_config` が失敗したときは結果ファイルを書かない。書き出し本体の例外では書く。
